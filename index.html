Code Mode for every CLI. One process, not 25.

A library your CLI embeds. Agents like Claude Code, Codex and Cursor send one small program to mycli code run. It runs inside the CLI, in one process, and returns typed results.

01 / the idea

Put the code loop in the CLI, not only in the agent.

Claude Code's Code Mode (experimental) puts the loop in the agent: Claude writes one JavaScript snippet that makes many tool calls, so model round trips drop. But when that snippet runs kubectl 25 times, it still starts 25 processes. Each one re-reads config, re-authenticates, re-parses arguments and prints raw text that has to be parsed back. CLI CodeMode moves the loop into the CLI: one kubectl code run, one process, typed operations in-process. The two compose: Claude Code's Code Mode can call kubectl code run - once instead of 25 commands.

02 / what you get

What the CLI gives an agent.

a

Embedded

No MCP server, sandbox service, Node or V8 required. A pure-Go library in your binary.

b

Self-describing

code capabilities --json, describe, docs and a generated SKILL.md. One global skill works for every compatible CLI.

c

Checked before it runs

code check returns file:line:col diagnostics and executes nothing.

d

Parallel and streaming

Promise.all, bounded pmap, and streams that kill the process on early stop.

e

Wrap, don't rewrite

Adapters turn your existing flag sets and commands into operations. Never a second implementation of a verb.

f

Workflows as plain JS

Export to WFNexus YAML, validated by its own parser and dry run.

03 / the numbers

Small, fast to start, honest about compute.

Same work, fresh process each run, medians, Apple Silicon. Workflows that call operations are fastest because there is no runtime to boot. Tight loops are within about 2x of Node's JIT; heavy compute belongs in a Go operation.

04 / quick start

Three steps in your CLI.

  1. Get it

    go get github.com/muthuishere/clicodemode@latest && go mod tidy

  2. Register an operation, mount code

    reg := codemode.NewRegistry("mycli 1.4.0")
reg.MustRegister(codemode.Operation{
    Name:        "health.check",
    Description: "Report whether this machine is healthy.",
    InputSchema: json.RawMessage(`{"type":"object","properties":{"verbose":{"type":"boolean"}}}`),
    SideEffects: codemode.SideEffectNone,
    Idempotent:  true,
    Handler: func(ctx context.Context, args map[string]any) (any, error) {
        return existingHealthCheck(args["verbose"] == true), nil // wrap, don't rewrite
    },
})
os.Exit(codemode.NewCLI(codemode.NewEngine(reg), "mycli code").Main(ctx, os.Args[2:]))

  3. Let the agent run one program

    mycli code capabilities --json   # what can I do?
mycli code check prog.js         # diagnostics, nothing runs
mycli code run prog.js           # run it

// prog.js
const [h, disk] = await Promise.all([
  call("health.check", { verbose: true }),
  ops.disk.usage({ path: "/" }),
])
export default { health: h, disk }

Try it without writing code: go run ./cmd/democli code help.

05 / security

Safe by default. Not a sandbox for hostile code.

Programs can only reach operations you registered. Exec is denied unless allowlisted, argv is never shell-parsed, child environments are minimal, cwd is confined, and step, time, depth and concurrency limits cannot be caught by the program.

But operations run with your CLI's privileges. Register only what you would let a program do, and gate calls with Policy.Allow. The language is a limited JavaScript subset: no class, switch or regex yet, and unsupported constructs fail at parse time with a clear message.
